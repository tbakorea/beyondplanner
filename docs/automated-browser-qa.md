# Mac에 의존하지 않는 플래너 검증

GitHub Actions의 `Planner browser QA`는 push, PR, 수동 실행 때 Linux에서 실제 앱을 실행한다. Mac 로그인이나 화면 잠금 여부와 관계없다.

- WebKit: 390×844, 430×932, 768×1024. Chromium: 1366×900.
- 상단 헤더와 날짜 행의 겹침/빈 공간, 메뉴의 화면 이탈, 화면 안에 보이는 업무 수를 확인한다.
- 입력, 완료 표시, 지연된 HTTP 저장 동안의 움직이는 시계, 저장 응답 후 데이터를 확인한다.
- 캐시 없는 새 브라우저 컨텍스트에서 HTTP 원본을 다시 읽어 수정·완료가 유지되는지 확인한다.
- 스크린샷·실패 추적·HTML 보고서는 실행의 `planner-browser-evidence`에서 14일간 확인한다. 데이터는 가상 QA 자료뿐이다.

## 검증 범위 구분

브라우저 검사는 실제 배포 코드와 독립 HTTP 저장소를 사용한다. Supabase 인증·RLS·운영 DB 저장 성공을 증명하지 않는다. 기존 Python 검사는 운영 API의 원자적 쓰기·보호 로직을 별도로 검사한다.

`Planner production reachability`는 Production 배포 성공 이벤트 또는 수동 실행에서 공개 HTML·버전별 JS/CSS·DB 설정의 접근성만 검사한다. 인증 또는 DB 쓰기를 하지 않는다. 배포 연동이 GitHub에 이벤트를 보내지 않으면 Actions에서 수동 실행한다.

실제 DB를 통한 쓰기 검증은 운영 사용자와 분리된 전용 QA 계정/프로젝트가 마련된 후 연결해야 한다. 사용자 계정, 운영 백업 또는 인증 토큰을 저장소·로그·스크린샷에 넣지 않는다. 전용 계정이 없는 현재 단계에서 이를 '운영 저장 검증 완료'로 보고하지 않는다.

## 완료 보고

결과를 코드 검사 / 브라우저 화면·격리 HTTP 검사 / 공개 배포 접근 검사 / 실제 DB 저장 검사로 구분한다. 검사 실패 상태에서 '전체 검증 완료'라고 보고하지 않는다. 실제 iPhone Safari 터치·키보드·앱 강제 종료는 WebKit 자동 검사의 범위를 벗어나므로 별도 검증한다.

## 실행

Node 22, Python 3.12에서 `npm ci`, `npx playwright install --with-deps chromium webkit`, `npm run test:browser`를 실행한다. 8765 포트가 비어 있어야 한다. 테스트 서버는 127.0.0.1에만 바인딩하며 실제 DB 연결 코드는 없다.
